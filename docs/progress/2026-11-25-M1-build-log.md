## 3. How it was built (key decisions)

### 3.1 Contract generated from code, with a drift check
The plan said "hand-write JSON Schemas, then mirror them in Pydantic". That means keeping two copies in sync by hand. Instead:

```
backend/app/schemas/*.py  ──export_contracts.py──▶  shared/contracts/openapi.yaml + schemas/*.json
                          ──make_examples.py────▶  shared/contracts/examples/*.json  (MSW mocks)
```

- The contract is still a reviewed, committed artifact, so its diff shows in every PR.
- `tests/test_contracts.py` and the CI step `export_contracts.py --check` fail if code and contract drift apart.
- Every example is validated against **both** its JSON Schema and its Pydantic model. Live API responses are validated against the schemas too.
- All contract models use `extra="forbid"`, so unknown fields (e.g. an LLM adding `"execute": ...`) are rejected.

`AGENTS.md §3` and `phase-0-setup.md` were updated to describe this.

### 3.2 Pipeline seam for M3 (`app/services/jobs/stages.py`)
M1's runner calls three named stages. Until M3 registers real ones, **safe stubs** run:

| Stage | Stub behaviour | Why it's safe |
|---|---|---|
| `verify` | every step `inconclusive` | can never produce a false "incorrect" |
| `recognize` | raises `RecognitionUnavailable` | learner gets a typeable placeholder region (`failed_recognition`) |
| `reason` | raises `ReviewUnavailable` | result is `completed_without_ai`, with verification kept |

M3 only calls `register_stage("verify", verify_steps)` etc. The exact signatures are now in `docs/team/M3-math-ai.md`.

### 3.3 Spec rules enforced in the runner (defence in depth)
- **No verdict before OCR confirmation:** any line below `OCR_CONFIDENCE_THRESHOLD` → `awaiting_confirmation`, and verify is not called (tested with a spy).
- **SymPy is the authority:** if the LLM's `status`/`first_error_step` disagree with verification, they're overwritten and `overridden: true` is set.
- **Original work is preserved:** OCR text is never overwritten; learner corrections go in `corrected_latex`.
- **Fail visibly:** LLM down, timeout or invalid output → `completed_without_ai` plus `ai_status` (`unavailable` / `invalid_output`). A verifier crash makes all steps `inconclusive`, never a lost submission.
- **Coordinates:** recognizers return crop-relative boxes; the runner converts them to page-normalized ones so M2 can draw annotations directly.

### 3.4 Upload security (T2.3, spec §13.2)
File type checked by magic bytes (a renamed `.exe` → 415), size limit → 413, dimension limit and decompression-bomb guard → 422. The image is re-encoded to PNG (strips EXIF and any trailing payload), and the client's filename is never used on disk. All of this is tested.

### 3.5 Bugs the tests caught (all fixed)
1. **Shared `Path()` object.** Two path params shared one FastAPI `Path(...)` instance, so `page_id` received the notebook id. Fixed with `Annotated` types.
2. **Foreign-key insert order.** Enabling `PRAGMA foreign_keys=ON` showed a child row could be flushed before its parent. Fixed with explicit flushes. FK checks are now on in tests too.
3. **In-memory SQLite across threads.** One shared connection isn't thread-safe. The background-mode test now uses a file DB, and production uses WAL + busy timeout.

**T7.7, what was built and found**
- **Export / delete my data:** `GET /learners/me/export`, `DELETE /learners/me/data?confirm=true`. Delete removes rows and uploaded images, keeps shared concepts/problems, refuses while a job is running, and only deletes files inside `UPLOAD_DIR`.
- **Ownership:** every id-taking endpoint returns 404 for another learner's id. A mutation check (owner check removed) made the test fail, so it really guards this.
- **Fuzzing (schemathesis):** every operation gets 30 generated requests. It found two real bugs, both fixed with regression tests:
  1. 405 responses had no `Allow` header, and Starlette alone would list only one route's methods.
  2. A body that isn't valid UTF-8 returned a 400 the contract didn't mention.
- **Local-only AI:** startup fails if `OLLAMA_URL` points off the machine/LAN, unless `ALLOW_REMOTE_OLLAMA=true`.
- **Scans:** bandit clean, pip-audit no known vulnerabilities, git history has no secrets.
